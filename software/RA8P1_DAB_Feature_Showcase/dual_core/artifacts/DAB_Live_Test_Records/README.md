# DAB 实测有效数据与调参记录

本目录只保存可直接检索、分析和训练的数据成果，不保存每次串口操作产生的零散日志。

## 文件规则

- 每一种电压、负载或功率工况只对应一个 CSV；重复测试追加到原文件并按 `source_file + sequence` 去重。
- `INDEX.csv` 汇总各工况样本数、来源文件数、平均值和相移范围。
- `CONDITION_MAP.csv` 记录原始采集文件属于哪个工况。以后同一工况继续使用相同的 `condition_file` 文件名。
- `TUNING_NOTES.md` 只记录能复用的调参结论、外部仪表读数和被排除数据的原因。
- 原始串口记录仅作可追溯证据，继续留在原历史测试目录且不得复制到这里；本专用目录只保留按工况合并后的有效数据和调参结论。

文件名带 `FWVIN`、`FWVOUT` 或 `FWPOUT` 表示该值仅来自固件 ADC/计算结果，没有同步记录独立仪表标签；它可以用于控制状态和趋势分析，但不能冒充独立效率测量。没有 `FW` 前缀的电源电压、负载和输出功率来自当次人工记录或外部仪表，其中外部标签仍是稀疏标签，并非每个采样点都独立测量。

## 有效样本准入条件

只有同时满足以下条件的行才进入工况 CSV：

- `control_on=1`、`pwm_on=1`，即采样时确实处于传功控制状态；
- `fault_hex=0`、`adc_valid=1`；
- `state_code` 为 6 或 7，`phase_ns>0`；
- 固件计算的输入和输出功率均大于 2 W；
- 已在 `CONDITION_MAP.csv` 中明确归属工况。

脚本发现“有效但尚未映射”的新采样会直接报错，不会静默丢弃，也不会自动制造含义不明的新文件。

## 后续追加流程

1. 串口采集完成并关闭端口后，把原始采集先交给现有规范化脚本生成 `telemetry.csv`。
2. 在本目录 `CONDITION_MAP.csv` 中增加一条来源映射；同一工况必须复用已有 `condition_file`，新工况才创建清晰的新文件名。
3. 运行双核工程 `tools/Consolidate-DabValidPowerData.ps1`。脚本会筛选传功行、追加、去重并重建 `INDEX.csv`。
4. 把外部电源、万用表、示波器或负载读数写入映射和 `TUNING_NOTES.md`；固件 ADC 与外部仪表不得混写成同一种真值。

当前整理结果共 7 个工况、4743 个有效传功样本。2026-08-11 的采样因 PWM 期间 ADC 共模干扰而全部排除，详见 `TUNING_NOTES.md`。
